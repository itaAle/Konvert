## What it is
Konvert is an Apple-style audio/video/image/PDF/Word converter for 64-bit Windows 10/11, macOS 11+ on
Apple Silicon and Linux (x86_64 and arm64).
It uses Tauri 2.11, React 19 with TypeScript, bundles FFmpeg/FFprobe and lays out Word documents with the Typst library.
It works **entirely offline, on the user's computer**.
**Public** repository: https://github.com/itaAle/Konvert (branch `main`).
Releases ship a Windows NSIS installer, macOS/Linux packages and a `.sha256` file for each: `v0.1.0` to `v0.4.0` are published (0.4.0: more formats, EXIF, SVG, PDF; first release with Linux arm64); `v0.5.0` (PDF page tools) is published; `v0.6.0` (Compress, Word documents) is next.
The `ffmpeg-n9.0.2-36` pre-release mirrors the FFmpeg build and its sources (required by the LGPL).

## Architecture
Cargo workspace (`Cargo.toml`, resolver 3, toolchain pinned to 1.99.1 in `rust-toolchain.toml`):

- `crates/konvert-core/`: pure domain logic, no Tauri.
  - `formats.rs`: declarative catalog with `TargetFormat`, `FORMATS` (FormatSpec), `RULES`, `available_targets`, `is_offered`. Pictures are `FormatKind::Image` with a single `ImageCodec` (JPG, PNG, WebP, AVIF, BMP, TIFF, GIF, ICO).
    - A format's id is its serialized `TargetFormat` name (`TargetFormat::id`/`from_id`, CLI `--to alac`). Formats may share an extension (ALAC/AAC `.m4a`, still/animated WebP and GIF): `source_format(media, input)` uses the extension, the kind of content and `detect_codecs`.
    - `secondary: true` formats are shown under "More formats" in the UI.
    - Groups (`TargetGroup`): video, audio, audioOnly, image, frames (pictures from a video), pages (pictures of PDF pages), document (PDF). Animations (GIF, animated WebP, APNG) share the GIF limits (`VideoCodec::is_animation`).
  - `probe.rs`: ffprobe (including `-show_stream_groups`) → `MediaInfo`.
    - Still pictures (`image2`/`*_pipe` demuxers, HEIF/AVIF brands) are `MediaKind::Image` with `PictureInfo` (alpha, AVIF alpha plane, HEIC grid, EXIF); animated GIF/APNG/WebP stay videos.
    - For non-HEIF pictures a second ffprobe reads the first frame (`apply_first_frame_json`): EXIF orientation and EXIF presence. Stored dimensions are the displayed (already rotated) ones.
    - FFmpeg applies the rotation (EXIF or `irot`) by itself before the filters; `[0:g:N]` in a filter graph returns the reassembled HEIC grid.
    - Video streams also report their displayed size: a quarter-turn display matrix swaps width and height, so resized portrait videos keep their proportions.
  - `request.rs` → `plan.rs` (`plan_conversion`, pure) → `command.rs` (`build_from_plan`, pure FFmpeg arguments) → `convert.rs` (execution).
  - `estimate.rs`: size estimate and warnings.
  - New modules: `exif.rs`, `svg.rs`, `metadata.rs`, `pdf.rs` (see below).
  - Other modules: `naming.rs` (`name (n).ext`, never overwrite), `workspace.rs` (`%TEMP%\Konvert\run-…` with a lock and cleanup after crashes), `process.rs` (kill-on-close Job Object and `CREATE_NO_WINDOW`), `progress.rs`, `disk.rs`, `binaries.rs`, `error.rs`.
  - Stable error codes in `error.rs`: `engine_missing`, `input_not_found`, `output_unavailable`, `not_media`, `corrupt_input`, `unsupported_conversion`, `invalid_pages`, `pdf_encrypted` (a password is needed), `pdf_wrong_password`, `disk_full`, `permission_denied`, `cancelled`, `no_gain` (a smaller copy would not be smaller), `engine_failed`, `io`. Each has an i18n message.
  - FFmpeg always runs with `-protocol_whitelist file`, and inputs are passed as `file:` URLs.
  - Pictures: `plan.rs::plan_picture` → `plan_still` → `ImagePlan` (always re-encoded); `command.rs::picture_args` (one filter graph: grid/alphamerge, scale, white background for JPG/BMP, alpha plane for AVIF, palette for GIF; encoders mjpeg, png, libwebp, libaom-av1 still-picture, bmp, tiff, gif; muxers `image2pipe`/`webp`/`avif`/`gif`/`ico`).
    - ICO: `ImagePlan::icons` (16/32/48/256 px up to the picture's size, each fitted into a transparent square), one PNG stream per size into the `ico` muxer (`command.rs::icon_args`). `.ico` inputs are pictures (largest stream; the first-frame probe selects that stream by index).
    - Frames from videos: `plan_frames` → `ConversionPlan::frames` (`FramePlan`). One frame: `-ss` before `-i`, clamped inside the video. A series: `fps=1/N` (or every frame with `-fps_mode passthrough`) into the `image2` muxer, written in `workspace.job_dir(id)` (`%` escaped in the pattern), then `naming::move_series` creates a new folder `name[ (n)]` with `name-001.ext`…; `ConversionOutcome::files` > 1 means `output` is a folder.
  - EXIF (`exif.rs`, no dependency): `extract` reads the TIFF block from JPEG/PNG/WebP/HEIF/AVIF, `prepare` sets Orientation to 1, drops IFD1 (thumbnail), writes the new pixel size and, for "remove location", zeroes the GPS directory and unlinks it; `insert` writes JPEG APP1, PNG eXIf, WebP EXIF (VP8/VP8L converted to VP8X) or an AVIF `Exif` item (iinf + iloc + iref cdsc, data offsets after `meta` shifted, payload in a new `mdat`). `convert.rs::finish_exif` runs after FFmpeg in the workspace (`ImagePlan::copy_exif`); if the copy fails and the location must go, `strip` removes all EXIF. The probe sets `PictureInfo::exif_copyable` and `MediaInfo::has_location` (GPS, or video `location*`/Apple ISO6709 tags). `little_exif` (no lossy WebP) and `img-parts` (no HEIF) were evaluated and rejected.
  - Location: `ConversionRequest::remove_location` → `ConversionPlan::remove_location` (only if the file has one); for audio/video, `-metadata location= -metadata location-eng= -metadata com.apple.quicktime.location.ISO6709=`.
  - Tags and covers: `FormatSpec::tags` (false for raw AC3/E-AC3/MP2 → `TagsDropped`), `cover_art` (attached picture: MP3, M4A, ALAC, FLAC, AIFF with `-write_id3v2 1`) and `cover_art_tag` (Ogg/Opus: `metadata.rs` builds a FLAC picture block, base64, in an `ffmetadata` file passed as a second input with `-map_metadata:s:a:0 1:g`).
  - Optional encoders: `FormatSpec::requires_encoder` (JPEG XL → libjxl); `engine_encoders` + `formats::supported_targets` filter what the app and the CLI offer (the macOS build has no libjxl). The picker/associations list `.jxl` everywhere but macOS (`LIBJXL_EXTENSIONS` in `commands.rs`).
  - SVG (`svg.rs`, resvg): detected before ffprobe, intrinsic size from usvg; `ImagePlan::render` is the drawing size (vector: `max_dimension` may enlarge, icons get every size); `convert.rs` renders a PNG in the workspace and FFmpeg encodes it. Never reads files named by the SVG (string href resolver disabled), catches panics, caps size at 16384 px / 100 MP. Test SVGs have no `xmlns` URL (the privacy check rejects URLs in code; usvg accepts elements without namespace).
  - PDF (`pdf.rs`: hayro 0.8 reads and draws, lopdf 0.46 without default features writes; pure Rust, no network): `.pdf` inputs are detected before ffprobe as `MediaKind::Document` with `DocumentInfo` (pages, first page size). Password-protected files → `pdf_encrypted` (hayro opens files with an empty user password). `FormatKind::Document` target `Pdf` (no muxer: written by Konvert).
    - Passwords (`secret.rs`): `Secret` (Debug `Secret(***)`, serialized as `""`, wiped with `fill(0)` + `black_box` + fence on drop; no crate) and `Passwords` (by path, Debug shows the count). `pdf::unlock` (only when `/Encrypt` is present and hayro reports `PasswordProtected`) decrypts with lopdf (`LoadOptions::with_password`, user or owner password; RC4/AES-128/AES-256 tested), saves the plain document in memory; `lopdf::Error::InvalidPassword`/`IncorrectPassword` → `pdf_wrong_password`. `pdf::load(path, password)` is how every PDF job reads its input; `probe_with` sets `DocumentInfo::locked`; `ConversionJob`/`CombinedJob::passwords`; plan warning `PdfUnlocked` for a PDF output of a locked input without protection. Limits: lopdf's own copies (its `LoadOptions` string, the derived keys in `EncryptionState`) and the WebView's JS strings are not wiped.
    - Protection: `PdfOptions::protection` (`PdfProtection`: `password: Secret`, `allow_print`, `allow_copy`) → `pdf::Finishing` in `build` (and `pdf::protect` for Word → PDF): AES-256 R6 (`EncryptionVersion::V5`, `Aes256CryptFilter`), random 32-byte key and trailer `ID` (`getrandom`), owner password = user password when nothing is restricted, else `Secret::random(32)`. Compress output is never protected. hayro reads lopdf's AES-256 output (cross-check in tests).
    - Pictures → PDF: `plan_document` places the picture (`pdf::place`: A4/Letter/fit, orientation, margins 0/14/42 pt) and plans a JPEG (preset → full size, 300 or 150 dpi on paper); `convert.rs::run_build` encodes it with FFmpeg in the workspace, then `pdf::build`. Pages are copied one by one (inherited MediaBox/CropBox/Rotate/Resources copied; metadata and Info dropped; Info has only `Producer: Konvert`).
    - PDF → pictures: `plan_pages` (`DocumentPlan` pages/dpi, `pdf::parse_pages` `1-3, 5, 8-` → `invalid_pages`); `run_pages` renders on a blocking thread (channel of 2 pages, `AtomicBool` stop, panics caught, 600 dpi and 100 MP caps), PNG written directly, JPG/WebP through FFmpeg. One page → one file next to the PDF; several → `naming::move_series_named` folder `name/name-<label>-NN.ext` (label from `PdfOptions::page_label`, letters only).
    - Several files → one PDF: `CombinedJob` + `run_combined` (named after the first file, or a folder named after it when split), IPC `start_combined`. `PdfPage::file` is the index of the file in `inputs` (0 for a single PDF); `pdf::check_pages` checks a layout of several files, `pdf::pages_of_file` takes one file's pages out of it. A layout with a Word document → `invalid_pages` (its pages exist only once laid out).
    - PDF → PDF (page tools, one PDF): `PdfOptions::layout` (pages in the new order, each with a clockwise turn; left-out pages absent; `None` = untouched) and `split` (`none`/`every` + `split_every`/`after` + `split_after` positions). `plan_document` checks them (`pdf::check_layout`, `pdf::split_sizes` → `invalid_pages`) into `DocumentPlan` `pages`/`rotations`/`parts`; `DocumentInfo::bookmark_pages` (pages bookmarks lead to, read with hayro in the probe) and `form` (`PdfForm` none/fillable/fixed) → `PdfBookmarksDropped` only when a bookmark's page is left out, `PdfFormFixed` for XFA or signed forms.
    - `convert.rs::run_build` (single PDF edits, pictures → PDF and combined files alike) → `pdf::build(parts, layout, sizes)` on a blocking thread (each file loaded once as `Source`, one `Writer` per part, cancellation between parts; files with no page in the layout are not read or encoded). `Writer::add` numbers every page of the part first, then `Writer::import` copies only what each page reaches, with new numbers per (file, object) (`copied`, so fonts shared by pages of a file are copied once); pages of the file not in this part, their annotations (`Source::annots`) and document-level objects stay behind and references to them become null; named destinations become explicit, dead links and null annotations are removed, page `Metadata`/`PieceInfo`/`LastModified` are dropped, turns add to the (inherited) `Rotate`. lopdf's `prune_objects` is quadratic: do not use it.
    - Bookmarks (`Source::outline`, `Bookmark`): GoTo actions and names become explicit `Dest`s, other actions are copied; `Writer::place_bookmark` keeps an item whose page is here, retargets one whose page is gone to the first `Dest` of its surviving children, drops it when nothing is left; original order, `Count` from the open state, `PageMode /UseOutlines` kept; only files with a page in the part contribute.
    - Forms (`Source::form`, `None` for XFA or signed): `Writer::write_form` keeps the top fields copied with a kept widget, `prune_field` drops null kids, root names clashing with an earlier file get `_2`, `_3` (UTF-16 aware), `DR` merged (first file wins a name), `DA`/`Q`/`NeedAppearances` from the first form, `CO` filtered.
    - One document goes next to the others (`name.pdf`, never overwriting); a split goes into a folder `name/name-pages-01-03.pdf`, `name-page-04.pdf` (labels `page_label`/`pages_label`; positions instead of page numbers when pages were reordered).
    - Thumbnails: `pdf::thumbnails` (at most 48 pages per call, longest side ≤ 512 px, PNG `data:` URLs, which the CSP already allows), IPC `pdf_thumbnails`; photos in the editor: `convert::picture_thumbnail` (a PNG conversion with `max_dimension` in the workspace, ids from `1 << 48` in `AppState::thumbnails`), IPC `picture_thumbnail`.
  - Compress ("Comprimi", a smaller copy in the file's own format): `ConversionRequest::compress` (`CompressOptions`: level light/strong/max, `max_bytes` limit, `pages_as_pictures`, file `label`) with `target` = the file's own format (`compress::compress_format`: PDF, JPG/PNG/WebP/AVIF/JXL, every video and audio format; not HEIC/BMP/TIFF/ICO/SVG). `plan_conversion` → `compress::plan`; `plan::plan_offered` is the planner without the "is offered" check (PNG→PNG, FLAC→FLAC are "pointless" targets otherwise).
    - Media: `compress::Search` turns the level into ordinary requests (preset Small + `AdvancedOptions`: picture quality/side, video bit rate from bits per pixel and codec efficiency, 1080p/720p, 30 fps, audio bit rate, mono, 16-bit/44.1/22.05 kHz for lossless) plus `Attempt::palette` (PNG 256 colors: palettegen/paletteuse in `picture_args`) and `drop_exif` (Max). With a limit: ladders (pictures: lower quality, then smaller sides; animations; lossless audio) or a bit rate from the duration corrected up to twice by the overshoot (video, lossy audio). `convert.rs::compress_media` keeps the first attempt that fits, else the smallest.
    - PDF (`pdf_compress.rs`, no FFmpeg): a hayro `Device` records the largest placed size of each image XObject (transform maps pixels to points); a second pass decodes each candidate once (`RasterImage::with_rgba`: every filter/color space, alpha from SMask/Mask) and stores it for every step (dpi 200/144/96/72/60/50/40): photos JPEG (`jpeg-encoder`, progressive, 4:2:0), lossless sources also try PNG-predictor Flate and median-cut 256 colors (JPEG must be 25% smaller to win), ≤256 colors or ≤16 grays → indexed Flate 1–8 bits, gray RGB → DeviceGray; kept only if 3% smaller. Skipped: masks, soft masks, `Matte`, JBIG2/CCITT. Then metadata/thumbnails/PieceInfo dropped, Info = `Producer: Konvert`, unreachable objects removed, duplicate streams merged, fonts reduced (`pdf_fonts.rs`, below), Flate streams recompressed (level 9), saved with object + xref streams; lopdf writes the xref stream uncompressed, so `pack_xref_stream` rewrites it in place (Flate + PNG Up predictor). `pages_as_pictures` (opt-in) renders pages to JPEG and keeps that document only if smaller.
    - Fonts (`pdf_fonts.rs`, every level, lossless): TrueType programs (`FontFile2`) of simple fonts and of Type0 fonts with `Identity-H/V` (CIDToGIDMap identity or stream) keep only the glyphs shown; glyph numbers never change (`prune` empties unused `glyf` entries, follows composite components, rewrites `loca` short/long, `head` checksum adjustment) and layout/device tables go (`DSIG`, `GSUB`, `GPOS`, `GDEF`, `kern`, `hdmx`, `LTSH`, `VDMX`…; `cmap`, `post`, `name`, hinting stay). Codes come from every content stream (`Usage::scan`: pages, forms, tiling patterns, Type 3 glyphs, `q`/`Q`, `gs` fonts, `Do` into forms without resources); simple fonts keep every glyph a used code may reach (identity, cmap 3,0 with F0xx, 1,0, 3,1 through Latin-1/WinAnsi/MacRoman, `Differences` names via `post`/`uniXXXX`, else a broad Latin/Greek/Cyrillic set). Untouched: fonts of unreadable streams, of AcroForm `DR`, never seen in use, any font when text names an unknown font, CFF/Type 1/OpenType programs, gain < 10%. ttf-parser reads cmaps/post. `subsetter` (Typst) was evaluated: it renumbers glyphs and drops `cmap`, so PDFs would need new CIDToGIDMaps and could not use it for simple fonts. `konvert-cli fonts FILE.pdf` lists fonts and the reduction.
    - Never larger: `run_compress` returns `no_gain` when the result is not smaller than the file; the copy is `name-<label>.ext` (`compressed`/`compresso`).
  - Word documents (`docx/`, no FFmpeg, no other program): `.docx` inputs are detected before ffprobe (ZIP with `word/document.xml`) as `MediaKind::Text` with `TextInfo` (pictures, first page size, `simplified`). Targets: DOCX → `Pdf` (group document, with pictures and PDFs → one PDF), PDF → `Docx` (`TargetGroup::Text`), DOCX → DOCX only through Compress. Warnings `DocxLayout` (always), `DocxSimplified` (text boxes, charts, equations, objects, external pictures), `PdfToDocx`.
    - `docx::Package` (ZIP in memory, 512 MB per part guard), `read.rs` → model (`Document`: blocks of `Paragraph`/`Table`, `Section`s with page setup, columns, headers/footers default/first/even, footnotes, media). Formatting resolved docDefaults → style `basedOn` chain → own; theme fonts (`minorHAnsi`/`majorHAnsi`); lists computed from numbering.xml (counters per abstract definition unless restarted); fields PAGE/NUMPAGES dynamic, other fields keep their shown result; page breaks split paragraphs (Typst breaks pages between blocks only); tables with gridSpan/vMerge (rowspan), table-style borders; DrawingML and VML pictures (PNG/JPEG/GIF/WebP only), external links never fetched. XML read with local names only (no namespace URIs in the reader).
    - `typeset.rs`: model → Typst source (text always as Typst **strings**, never markup), fixed line box 0.8/0.2 em with leading from Word's spacing (single = 1.2 em), blocks with above/below/inset/fill, headings as `heading` (PDF bookmarks), tab stops as a `grid`, tables as `table.cell` with x/y/colspan/rowspan/stroke; fonts: system fonts scanned once (`typst_kit::fonts::system`, `OnceLock`) with metric-compatible alternates (Carlito, Caladea, Liberation…). `KonvertWorld` serves only `/main.typ` and the document's pictures. `only_konvert` replaces Typst's Creator/XMP with `Producer: Konvert`.
    - `from_pdf.rs` (PDF → DOCX): a hayro `Device` collects glyphs (Unicode, origin and size from `props.transform * glyph.transform()` at 1000 units per em, PostScript name/weight/italic, color), pictures (decoded, PNG or JPEG, deduplicated by object) and filled boxes. Lines: same baseline, then smaller rows within a larger row's height join it (super/subscripts); split at gaps > 1.6 em into pieces sharing a row number (table rows → tabbed paragraphs with tab stops). Two columns detected by a gutter; paragraphs from pitch, size/style changes, short lines, indents, list markers; headings = sizes ≥ 1.12× body text; text on a colored box gets the box as paragraph shading, light text elsewhere turns dark. `write.rs` writes the DOCX (elements in schema order: Word checks it; Heading1–3 styles; no docProps).
    - `compress.rs` (DOCX): pictures scaled to their shown size (`wp:extent`) at the PDF steps' dpi, JPEG stays JPEG, PNG stays PNG (256 colors from Strong, own PNG writer), thumbnail and its relationship removed, parts recompressed (Deflate 9, pictures stored).
    - The privacy check allows `http://schemas.openxmlformats.org/` (XML namespace names every DOCX must carry, never opened) only in `docx/write.rs`.
  - Tests: unit tests in the modules and `tests/engine.rs` (42 integration tests with real FFmpeg; the JPEG XL one skips itself without libjxl). `tests/fixtures/mod.rs` builds JPEGs with EXIF, grid HEIC files (HEVC tiles made with libkvazaar), PDFs (plain, with personal metadata, encrypted, with a photo, with a heavy drawing) and a Word-like DOCX (styles, list, merged cells, header with PAGE, footnote, picture) in memory.

## FFmpeg and licenses
- LGPL-3.0-or-later build, no GPL or nonfree parts: **no libx264/libx265/fdk-aac**.
- Available encoders: libopenh264 (H.264), libvpx/libvpx-vp9, libsvtav1, mpeg4, mpeg2video, gif, libwebp_anim, apng, libmp3lame, aac, alac, ac3, eac3, mp2, libopus, libvorbis, flac, wmav2.
- The build also has picture decoders and encoders (mjpeg, png, libwebp, libaom-av1, bmp, tiff, libkvazaar, …): check them with `ffmpeg -encoders`.
- Every encoder and muxer Konvert uses is native or in all three platform builds, except libjxl and librsvg: present in the BtbN Windows/Linux builds, missing from our macOS build.
- FFmpeg limits found while adding formats: the CAF muxer only takes ALAC/PCM (no AAC or Opus); the Ogg/Opus muxers reject attached pictures (cover art there needs a `METADATA_BLOCK_PICTURE` tag); an image2 output pattern treats `%` in folder names as a pattern, so it must be escaped as `%%`.
- H.264 patents are not covered by OpenH264's BSD license: the README already says so.
- A new Rust or npm library must have a compatible license and pass the privacy check. Then run `npm run licenses`.

## Practical notes for agents
- Auto mode blocks `powershell -ExecutionPolicy Bypass -File …` launched by the agent: run PowerShell code (e.g. UI Automation) inline instead. `npm run release` works.
- Real-app check without the file picker: `npx tauri build --debug --no-bundle`, then start `target/debug/konvert.exe` with the file as argument (same path as "Open with") and read the window with UI Automation (query twice to wake up WebView2's accessibility tree).
- UI in the browser: `npm run dev` (port 1420) with the fake backend; for the agents' preview, create `.claude/launch.json` (ignored by Git) with a `konvert-ui` configuration running `npm run dev` on port 1420; `?files=a.jpg|b.mp4` sets what the file picker returns.
- Drag & drop cannot be automated: ask the owner to try it by hand.
- Before starting a conversion in the real app, read the destination from the path text of the "Save to" row, or from `preferences.json`: the row's × button is named "Accanto al file originale"/"Next to the original" even when a folder is set. With a folder set, conversions go there: do not start them.
- UI Automation: buttons with `aria-pressed` (the scissors) expose `TogglePattern`, not `InvokePattern`; cards and segments expose `SelectionItemPattern`; a page is focused with `SetFocus()` and driven with `SendKeys`.
- Reading the real app with UI Automation: find the window by enumerating the `konvert` process windows with class `Tauri Window` and `AutomationElement.FromHandle` (searching by name from the root fails); redefine the `Add-Type` helper in every PowerShell call and do not name a C# method `Main`.
- The browser pane captures only part of the page at device pixel ratio 2: read it with `read_page`/`get_page_text`, or shift `#root` with a CSS transform just for the screenshot.
- `target/release/konvert.pdb` contains the user's path: never upload `target/` or `.pdb` files.
- FFmpeg 9: a 1×1 crop of 4:2:0 YUV fails (convert to rgba first); `-map 0:g:0` on a HEIC gives a single tile, `[0:g:0]` in a filter graph gives the whole photo.
